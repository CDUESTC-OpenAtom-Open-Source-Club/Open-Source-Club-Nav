# 04 - 后端中间件模块报告

> 模块路径：`backend/middleware/`  
> 分析文件：`auth.go`, `session.go`

---

## 1. 模块职责

中间件模块负责 HTTP 请求的认证和授权：
- `auth.go`：JWT Token 验证（SignAuth 中间件）
- `session.go`：管理员会话管理（基于 Cookie-Session 模式）

---

## 2. 代码质量评估

### 命名规范
- ✅ 函数命名清晰：`SignAuth()`, `GetSessionUser()`
- ⚠️ 文件命名不一致：`auth.go` 处理 JWT，`session.go` 处理 Session

### 注释质量
- ⚠️ 缺少中间件使用说明
- ⚠️ 认证流程缺少注释

---

## 3. 架构合理性评估

### 🔴 严重问题

1. **Session 生成算法完全可预测**
   - `session.go` 中的 Session ID 生成使用 `username + timestamp` 的简单拼接
   - 攻击者知道管理员用户名后，可以推算出合法 Session ID
   - **建议**：使用 `crypto/rand` 生成至少 32 字节的随机 Session

2. **双重认证机制混乱**
   - 同时存在 JWT（`auth.go`）和 Cookie-Session（`session.go`）两种认证方式
   - JWT 用于 API 调用，Session 用于管理员后台
   - 两种机制共存增加了维护复杂度和安全风险
   - **建议**：统一为一种认证方式，推荐 JWT + HttpOnly Cookie

3. **Session 无过期机制**
   - 生成的 Session 没有过期时间
   - 一旦泄露，攻击者可以永久使用
   - **建议**：添加 `expires_at` 字段，默认 24 小时过期

### ⚠️ 中等问题

4. **JWT 解析每次读配置文件**
   - `SignAuth` 中间件每次请求都调用 `utils.ParseJWT`
   - `ParseJWT` 内部每次读取配置文件获取 Secret
   - 高并发下性能差
   - **建议**：在中间件初始化时加载 Secret，缓存使用

5. **缺少 Token 刷新机制**
   - JWT Token 没有刷新策略
   - Token 过期后用户必须重新登录

6. **错误处理不统一**
   - 认证失败有的返回 401，有的返回 403
   - 错误消息格式不一致

## 4. 发现的问题和缺陷

| # | 文件 | 严重程度 | 问题描述 |
|---|------|---------|---------|
| 1 | session.go | 🔴 严重 | Session 生成算法可预测，使用 username+timestamp |

| 4 | auth.go | 🟡 中 | JWT Secret 每次请求重新读取配置文件 |
| 5 | 整体 | 🟠 低 | 缺少 Token 刷新机制 |
| 6 | 整体 | 🟠 低 | 认证失败响应格式不统一 |

---

## 5. 安全性问题

1. **🔴 Session 可伪造**：基于可预测信息生成 Session ID
2. **🔴 Session 永不过期**：没有过期时间，泄露后永久有效
3. **🟡 JWT Secret 频繁读取**：虽然不是直接安全问题，但增加了 Secret 泄露风险
4. **🟡 缺少 CSRF 保护**：Cookie-Session 模式需要 CSRF Token

---

## 6. 改进建议

1. **重写 Session 生成**：
   ```go
   func GenerateSession() (string, error) {
       b := make([]byte, 32)
       if _, err := rand.Read(b); err != nil {
           return "", err
       }
       return base64.URLEncoding.EncodeToString(b), nil
   }
   ```

2. **添加 Session 过期**：
   ```go
   type Session struct {
       Token     string
       ExpiresAt time.Time
   }
   ```

3. **统一认证方式**：推荐使用 JWT + HttpOnly Cookie

4. **缓存 JWT Secret**：在中间件初始化时加载

---

## 7. 总结

中间件模块存在 **Session 可伪造** 的严重安全漏洞，这是最紧急需要修复的问题。同时双重认证机制增加了系统复杂度，建议统一为 JWT 方案。
