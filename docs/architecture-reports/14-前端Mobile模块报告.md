# 14 - 前端 Mobile 模块报告

> 模块路径：`fronted/apps/mobile/`  
> 技术栈：Expo 54 + React Native 0.81 + Expo Router

---

## 1. 模块职责

Mobile 模块是项目的移动端应用，负责：
- 提供原生移动端体验
- 支持 iOS 和 Android
- 通过 Expo Router 实现导航

---

## 2. 代码质量评估

### 命名规范
- ⚠️ 目录命名不一致（`__create` 使用下划线前缀）

### 依赖管理
- 🔴 依赖数量极多（96 个依赖）
- 🔴 13 个 `.patch` 文件说明依赖兼容性问题严重

---

## 3. 架构合理性评估

### 🔴 严重问题

1. **补丁文件过多（13个）**
   - 大量使用 `patch-package` 修补第三方库
   - 说明项目依赖版本之间存在严重兼容性问题
   - 升级依赖时补丁可能失效
   - **建议**：审查每个补丁的必要性，寻找替代方案

2. **依赖数量过多（96个）**
   - 移动端引入了大量功能模块（相机、日历、地图、传感器、语音等）
   - 许多依赖可能未实际使用
   - 增加 App 体积和构建时间
   - **建议**：审计实际使用的依赖，移除未使用的

3. **polyfills 数量多（19个文件）**
   - 为 Web 平台兼容性添加了大量 polyfill
   - 增加了打包体积
   - 部分可以用现代 API 替代

### ⚠️ 中等问题

4. **与 Web 端共享代码少**
   - `fronted/shared/` 只有 2 个文件
   - Mobile 和 Web 之间的类型、工具、逻辑复用率低
   - **建议**：提取共享的 types、services、utils

5. **React 版本不一致**
   - Web 端使用 React 19.2.4
   - Mobile 端使用 React 19.1.0
   - 可能导致行为差异

---

## 4. 发现的问题和缺陷

| # | 严重程度 | 问题描述 |
|---|---------|---------|
| 1 | 🔴 严重 | 13 个补丁文件，依赖兼容性问题严重 |
| 2 | 🔴 高 | 96 个依赖，大量可能未使用 |
| 3 | 🟡 中 | 19 个 polyfill 文件，打包体积大 |
| 4 | 🟡 中 | 与 Web 端代码复用率低 |
| 5 | 🟡 中 | React 版本与 Web 端不一致 |
| 6 | 🟠 低 | 缺少 EAS Build 配置优化 |

---

## 5. 性能问题

1. **App 体积大**：96 个依赖导致打包体积过大
2. **启动时间长**：polyfill 和补丁增加了初始化时间
3. **热更新困难**：大量补丁可能影响 OTA 更新

---

## 6. 改进建议

1. **依赖审计**：移除未使用的依赖
2. **减少补丁**：寻找兼容的替代方案
3. **提取共享代码**：在 `fronted/shared/` 中共享类型和逻辑
4. **统一 React 版本**：与 Web 端保持一致
5. **优化 polyfill**：按需加载

---

## 7. 总结

Mobile 模块最大的问题是 **依赖兼容性问题严重**（13个补丁）和 **依赖数量过多**（96个）。建议优先进行依赖审计和清理，减少维护成本。
