# 06 - 后端工具模块报告

> 模块路径：`backend/utils/`  
> 分析文件：`jwt.go`, `logger.go`, `password.go`, `password_test.go`

---

## 1. 模块职责

工具模块提供通用的辅助功能：
- `jwt.go`：JWT Token 生成与解析
- `logger.go`：全局日志初始化与管理
- `password.go`：密码哈希与验证（bcrypt → scrypt 迁移）
- `password_test.go`：密码模块单元测试

---

## 2. 代码质量评估

### 命名规范
- ✅ 函数命名清晰：`GenerateToken`, `ParseJWT`, `InitLogger`
- ✅ 测试命名符合 Go 惯例

### 注释质量
- ⚠️ `jwt.go` 缺少 Token 格式说明
- ⚠️ `logger.go` 缺少日志级别使用指南

### 测试覆盖
- ✅ `password.go` 有单元测试
- 🔴 其他工具函数完全没有测试

---

## 3. 架构合理性评估

### 🔴 高风险问题

1. **JWT 每次生成/解析都重新读取配置文件**
   - `GenerateToken()` 和 `ParseJWT()` 每次都调用 `config.LoadConfig()`
   - 高并发下会导致大量文件 I/O
   - **建议**：初始化时加载一次 Secret，缓存使用

2. **Logger 初始化错误被忽略**
   - `InitLogger()` 中如果初始化失败，仅 `log.Printf` 打印
   - 程序继续运行但 `Logger` 为 nil，后续日志调用会 panic
   - **建议**：初始化失败应 `log.Fatalf` 终止程序

3. **密码迁移策略复杂**
   - `password.go` 实现了 bcrypt → scrypt 的自动迁移
   - 迁移逻辑增加了代码复杂度
   - 但如果确实需要从旧系统迁移，这个设计是合理的

### ⚠️ 中等问题

4. **全局 Logger 变量**
   - `Logger` 是包级全局变量，测试时难以 mock
   - **建议**：使用依赖注入或接口抽象

5. **JWT Claims 结构不标准**
   - 自定义的 Claims 结构缺少标准字段（`iss`、`aud`）
   - **建议**：添加 `RegisteredClaims` 嵌入

---

## 4. 发现的问题和缺陷

| # | 文件 | 严重程度 | 问题描述 |
|---|------|---------|---------|
| 1 | jwt.go | 🔴 高 | 每次 Token 操作重新读取配置文件 |
| 2 | logger.go | 🔴 高 | Logger 初始化失败被忽略，后续可能 panic |
| 3 | password.go | 🟡 中 | bcrypt → scrypt 迁移策略增加复杂度 |
| 4 | jwt.go | 🟡 中 | JWT Claims 缺少标准字段（iss, aud, iat） |
| 5 | logger.go | 🟠 低 | 全局变量难以测试 |
| 6 | jwt.go | 🟠 低 | Token 过期时间硬编码 |

---

## 5. 安全性问题

1. **🟡 JWT Secret 频繁读取**：增加了 Secret 泄露的风险窗口
2. **🟡 Token 过期时间硬编码**：无法根据安全需求调整

---

## 6. 性能问题

1. **🔴 配置文件重复 I/O**：每个 JWT 操作都读取配置文件
2. **🟡 Logger Sync**：`SyncLogger()` 在每次请求后调用可能影响性能

---

## 7. 改进建议

1. **缓存 JWT Secret**：
   ```go
   var jwtSecret []byte
   var secretOnce sync.Once
   
   func getJWTSecret() []byte {
       secretOnce.Do(func() {
           cfg := config.LoadConfig()
           jwtSecret = []byte(cfg.JWT.Secret)
       })
       return jwtSecret
   }
   ```

2. **Logger 初始化失败处理**：
   ```go
   func InitLogger() {
       var err error
       Logger, err = zap.NewProduction()
       if err != nil {
           log.Fatalf("failed to init logger: %v", err)
       }
   }
   ```

3. **添加更多单元测试**：JWT 和 Logger 的测试

---

## 8. 总结

工具模块最严重的问题是 **JWT Secret 每次请求都重新读取配置文件**，在高并发场景下会成为性能瓶颈。Logger 初始化失败处理不当也是一个需要修复的隐患。
