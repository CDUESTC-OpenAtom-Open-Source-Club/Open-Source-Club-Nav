# 07 - 后端数据库迁移模块报告

> 模块路径：`backend/db/migrate/`  
> 分析文件：`migrator.go` + `migrations/*.sql`

---

## 1. 模块职责

数据库迁移模块负责：
- 版本化管理数据库 Schema 变更
- 自动执行未应用的迁移文件
- 校验已应用迁移的完整性（Checksum）
- 初始化种子数据

---

## 2. 代码质量评估

### 命名规范
- ✅ 迁移文件按序号命名：`001_schema.sql`, `002_seed_accounts.sql`, `003_seed_data.sql`
- ✅ `migrator.go` 代码结构清晰

### 注释质量
- ⚠️ SQL 文件中部分注释与实际行为不符（如声称"幂等"但实际上不幂等）

---

## 3. 架构合理性评估

### 🔴 高风险问题

1. **迁移不使用事务**
   - 如果迁移文件中某条 SQL 失败，已执行的语句不会回滚
   - 数据库将处于不一致状态

2. **种子数据不幂等**
   - `nav_items` 表使用自增主键，`ON DUPLICATE KEY UPDATE` 永远不会触发（没有唯一键约束）
   - 每次迁移都会插入重复数据
   - `resource_matrix` 完全没有幂等保护

3. **SQL 解析器不健壮**
   - 自定义的 `splitSQLStatements` 不支持块注释 `/* */` 和 `DELIMITER` 语法

4. **模型与 Schema 不匹配**
   - `nav_item_health` 和 `nav_item_logs` 表结构与 Go 模型字段名不一致
   - `nav_items` 表有 `icon_url` 但模型中无映射

5. **种子数据默认弱密码**
   - admin 和 editor 使用 `admin123` 作为默认密码
   - 密码明文写在 SQL 注释中

---

## 5. 安全性问题

1. **🔴 默认弱密码**：admin 和 editor 均使用 `admin123`
2. **🟡 密码明文注释**：SQL 文件中直接暴露默认密码

---

## 6. 改进建议

1. **添加事务支持**：将每个迁移文件包裹在事务中
2. **修复幂等性**：为种子数据添加唯一键约束或使用 `INSERT IGNORE`
3. **使用成熟迁移工具**：考虑 `golang-migrate` 或 `goose`
4. **移除密码明文注释**
5. **修复模型与 Schema 不匹配**

---

## 7. 总结

迁移模块的核心问题是 **事务缺失** 和 **种子数据不幂等**，这两点在生产环境中会导致数据不一致。建议优先修复，或考虑迁移到成熟的数据库迁移工具。
