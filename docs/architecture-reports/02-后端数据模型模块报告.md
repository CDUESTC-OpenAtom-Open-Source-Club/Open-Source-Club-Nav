# 02 - 后端数据模型模块报告

> 模块路径：`backend/model/`  
> 分析文件：`articles.go`, `friend_links.go`, `metrics.go`, `mini_games.go`, `misc.go`, `nav_items.go`, `resource_matrix.go`, `users.go`, `works.go`

---

## 1. 模块职责

数据模型模块定义了与数据库表对应的 GORM 模型结构体，负责：
- 定义数据库表的 Go 结构体映射
- 指定字段类型、约束和 GORM 标签
- 定义表名映射

---

## 2. 代码质量评估

### 命名规范
- ✅ 结构体命名符合 Go 惯例，使用大驼峰
- ⚠️ 部分字段命名不一致：有的用 `ID`，有的用 `NavitemID`

### 注释质量
- ⚠️ 大部分模型缺少注释说明
- ⚠️ 字段约束和业务含义缺少文档

---

## 3. 架构合理性评估

### 🔴 高风险问题

1. **NavItem 主键冲突**
   - `nav_items.go` 模型中使用自增 `ID` 作为主键
   - 但部分业务逻辑（如友链、小游戏）使用 `NavItem` 作为统一容器
   - 主键策略不清晰，容易导致数据冲突

2. **模型与数据库 Schema 不匹配**
   - `nav_items` 表有 `icon_url`、`cover_url`、`created_by`、`updated_by` 字段，但模型中部分未映射
   - `nav_item_health` 表结构与模型字段名不一致（`link_id` vs `NavItemID`）
   - `nav_item_logs` 表结构与模型不匹配

3. **misc.go 职责混乱**
   - 一个文件中定义了多个不相关的模型：`Content`、`DailyStat`、`NavItemHealth`、`NavItemLog`、`LoginAuditLog`
   - 应该按领域拆分为独立文件

### ⚠️ 中等问题

4. **缺少模型验证**
   - 没有使用 GORM 的 `BeforeCreate`/`BeforeUpdate` hook 做字段校验
   - 依赖 handler 层手动验证

5. **硬编码的 JSON 标签**
   - 部分字段使用 `json:"-"` 忽略序列化，但没有统一标准

---

| # | 文件 | 严重程度 | 问题描述 |

## 5. 安全性问题

1. **🟡 User 模型序列化风险**：`PasswordHash` 和 `Session` 字段如果未正确标记 `json:"-"`，可能在 API 响应中泄露

---

## 6. 改进建议

1. **拆分 misc.go**：
   ```
   model/
   ├── content.go      # Content 模型
   ├── daily_stat.go   # DailyStat 模型
   ├── nav_health.go   # NavItemHealth 模型
   ├── nav_log.go      # NavItemLog 模型
   └── login_audit.go  # LoginAuditLog 模型
   ```

2. **修复模型与 Schema 不匹配**：
   - 添加缺失的 `icon_url`、`created_by`、`updated_by` 字段
   - 统一 `NavItemHealth` 和 `NavItemLog` 的字段命名

3. **添加模型验证 Hook**：
   ```go
   func (u *User) BeforeCreate(tx *gorm.DB) error {
       if u.Username == "" {
           return errors.New("username is required")
       }
       return nil
   }
   ```

4. **添加数据库索引**：
   ```go
   type User struct {
       Session string `gorm:"index" json:"-"`
   }
   ```

---

## 8. 总结

数据模型模块存在模型与数据库 Schema 不匹配的核心问题，`misc.go` 的职责混乱增加了维护难度。建议按领域拆分模型文件，并修复所有字段映射不一致的问题。
